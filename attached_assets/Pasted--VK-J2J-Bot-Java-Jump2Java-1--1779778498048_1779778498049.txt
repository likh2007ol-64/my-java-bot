ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) на разработку VK-бота «J2J_Bot» для сообщества «Java старт | Jump2Java»
1. Общие сведения
•	Название бота: J2J_Bot
•	Платформа: ВКонтакте (групповой чат сообщества и личные сообщения)
•	Цель:
o	Помогать студентам в изучении Java: отвечать на теоретические вопросы, используя загруженные учебники (русские и английские).
o	Выполнять и проверять Java-код, а при ошибке немедленно выдавать правильное решение с объяснением (режим «страховка»).
•	Принцип: Бот — учебный ассистент, не экзаменатор. Тестирование знаний не входит в функционал.
•	Объём MVP: базовая помощь без учёта прогресса студентов (учёт и аналитика будут добавлены в версии 2.0).
2. Функциональные требования
2.1. Ответы на теоретические вопросы (на основе базы знаний)
•	Студент задаёт вопрос на русском или английском языке.
•	Бот реализует многоязычный векторный поиск (Multilingual RAG):
1.	Преобразует запрос в вектор с помощью многоязычной эмбеддинг-модели BAAI/bge-m3 (без предварительного перевода).
2.	Выполняет поиск в векторной БД Chroma, где индексированы фрагменты учебных книг (PDF) на русском и английском языках.
3.	Находит 3–5 наиболее релевантных фрагментов.
4.	Передаёт найденный контекст + вопрос в DeepSeek API с инструкцией:
«Ответь на русском языке, основываясь строго на предоставленных фрагментах. Если ответа нет во фрагментах, скажи об этом. Не используй свои знания. Укажи источник(и) информации: название книги, автор, главу».
5.	DeepSeek генерирует ответ, который включает указание источников.
•	Контроль источников: генерация DeepSeek строго ограничена предоставленными фрагментами. Параметр temperature — 0.1–0.3.
•	Если ответ не найден в базе знаний (или найденные фрагменты не позволяют сформировать ответ), бот отправляет:
«Я не могу найти точный ответ на этот вопрос в нашей учебной базе. Попробуйте переформулировать запрос»
Вместе с изображением robot_sad.png.
•	Визуальное сопровождение:
При получении вопроса сначала отправляется robot_thinking.png с текстом «Секунду, думаю... 🤔», затем через 1–3 секунды — основной ответ (с соответствующей эмоцией: robot_happy.png или robot_sad.png).
2.2. Выполнение и проверка Java-кода (режим «страховка»)
2.2.1. Механизм выполнения
•	Бот распознаёт Java-код в сообщениях студента по команде /run или по обрамлению в тройные бэктики ```java ... ```.
•	Код отправляется на выполнение во внешний сервис JDoodle API (язык Java, версия 17).
•	Тарификация: на этапе тестирования используется бесплатный тариф JDoodle с лимитом 20 запросов в сутки на аккаунт.
•	Логика работы с лимитом:
o	Бот ведёт счётчик использованных запросов за текущие сутки (хранит в SQLite).
o	При достижении 20 запросов бот не отправляет код в JDoodle, а возвращает сообщение:
«⚠️ Дневной лимит проверки кода (20 запросов) исчерпан. Попробуйте завтра или обратитесь к администратору для перехода на платный тариф».
o	Сброс счётчика происходит в 00:00 UTC.
o	Администратор может просмотреть остаток запросов командой /jdoodle_status и при необходимости сбросить счётчик вручную (/reset_jdoodle_limit).
o	При переходе на платный тариф достаточно изменить переменную окружения JDODDLE_PLAN=pro (или JDODDLE_PLAN=free по умолчанию), и лимит перестанет проверяться.
2.2.2. Режим «Проверка и страховка» (немедленная выдача решения)
•	Студент отправляет Java-код.
•	Бот выполняет код через JDoodle API.
•	Если код выполнен успешно (ошибок нет):
o	Бот отправляет robot_happy.png и текст «✅ Код выполнен без ошибок. Молодец!» + вывод программы (stdout), если он есть.
•	Если код содержит ошибку (компиляции или выполнения):
o	Бот отправляет robot_sad.png и сообщение:
«Ошибка: [техническое сообщение от JDoodle]. Ниже — правильное решение с объяснением, чтобы ты мог разобраться».
o	Бот немедленно выдаёт эталонный правильный код (заранее подготовленный для данного задания или, если задание не распознано, генерирует корректный код через DeepSeek с обязательной проверкой).
o	К эталону прилагается пояснение на русском языке: почему это решение правильное, в чём была ошибка студента (если можно сопоставить).
•	Команда /explain позволяет студенту сразу запросить правильное решение без предварительной отправки своего кода. Бот выдаёт эталон + объяснение.
•	Важно: бот не требует от студента нескольких попыток и не ведёт счётчик ошибок. При первой же ошибке (или по запросу) даётся готовое решение.
2.3. Вспомогательные команды и сценарии
•	/start (или /help): приветствие с robot_greeting.png и текстом:
*«Привет! Я Java-робот 🤖. Помогаю студентам JUMP2JAVA с теорией, кодом. Спроси меня о Java — или отправь код на проверку»*.
•	/about: краткая информация о боте, версия.
•	/explain: немедленная выдача правильного решения (см. 2.2.2).
•	При получении вопроса или команды /run сначала отправляется robot_thinking.png с текстом «Секунду, думаю... 🤔» (отдельным сообщением). Затем через 1–3 секунды — итоговый ответ.
2.4. Визуальный и текстовый персонаж (статический робот)
Изображение (PNG)	Событие	Текст
robot_greeting.png	/start или первое обращение	«Привет! Я Java-робот 🤖. Помогаю студентам JUMP2JAVA с теорией, кодом. Спроси меня о Java — или отправь код на проверку»
robot_thinking.png	Бот начал обработку (вопрос или /run)	«Секунду, думаю... 🤔» (отдельным сообщением, затем пауза 1–3 сек)
robot_happy.png	Успешное выполнение кода / успешный ответ на вопрос	«✅ Код выполнен без ошибок. Молодец!» (или текст ответа)
robot_sad.png	Ошибка в коде / ответ не найден	«Ой, что-то пошло не так 😕» + пояснение / эталон
Изображения хранятся на сервере (BotHost) в папке static/. Формат — PNG, квадратные, прозрачный фон.
2.5. Административные команды (управление библиотекой и JDoodle)
Команды доступны только пользователю, чей VK ID указан в переменной окружения ADMIN_IDS (один администратор). При попытке выполнения обычным пользователем бот отвечает «У вас нет прав».
2.5.1. Интерфейс администратора через личные сообщения
•	Администратор пишет боту в ЛС команду /admin.
•	Бот отправляет сообщение с клавиатурой:
text
[🔄 Переиндексировать всё]   [🗑 Очистить базу]
[📂 Показать файлы]          [❌ Удалить файл/папку]
[📦 Обновить из ZIP]         [ℹ️ Статус библиотеки]
[JDoodle: статус]            [JDoodle: сброс лимита]
•	При нажатии на кнопку бот выполняет действие и присылает результат в ЛС.
2.5.2. Команды для управления библиотекой
•	/reload_knowledge – полная переиндексация книг (ответ с отчётом).
•	/clear_knowledge – очистка базы знаний (с подтверждением).
•	/list_files [путь] – просмотр файлов в хранилище.
•	/delete_file / /delete_folder – удаление (с подтверждением, запрет на удаление корневой Литература).
•	/update_library (опционально, версия 2.0) – обновление из ZIP.
•	/status – статус библиотеки (количество книг, чанков, дата последней индексации).
2.5.3. Команды для управления JDoodle
•	/jdoodle_status – выводит текущее количество использованных запросов за сегодня и лимит (20 или unlimited).
•	/reset_jdoodle_limit – принудительный сброс счётчика (полезно при тестировании).
3. Архитектура и стек технологий (MVP)
3.1. Платформы и инструменты
•	Среда разработки и прототипирования: Replit (с использованием Replit Agent).
•	Хостинг: BotHost (платный тариф «ПРО», постоянное дисковое хранилище).
•	Язык / фреймворк: Java 17 / Spring Boot 3 + Spring AI.
•	Система контроля версий: GitHub.
3.2. Базы данных
•	Векторная БД: Chroma (in memory или встраиваемая) — для эмбеддингов книг.
•	Реляционная БД: SQLite (для хранения лимитов JDoodle и логов индексации; учёт студентов не требуется в MVP).
3.3. Интеграции и ключевые библиотеки
•	VK API: Callback API, Messages API, поддержка клавиатур.
•	LLM для генерации ответов: DeepSeek API (модель deepseek-chat).
•	Эмбеддинг-модель: BAAI/bge-m3 (работает локально на сервере).
•	Выполнение кода: JDoodle API (бесплатный тариф с лимитом, при необходимости платный).
•	Извлечение текста из PDF: Apache PDFBox.
•	RAG-пайплайн в Java: LangChain4j (поддержка Chroma, эмбеддингов, LLM).
•	Работа с SQLite: JDBC + HikariCP (или Spring Data JDBC).
3.4. Процесс инициализации базы знаний
•	Папка с литературой: /app/shared/Литература (подпапки: Java Core, Инструменты, Фреймворки, Веб-технологии, Подготовка к собеседованию).
•	При развёртывании или по команде /reload_knowledge:
1.	Сканируется папка Литература.
2.	Из каждого PDF извлекается текст (Apache PDFBox).
3.	Текст разбивается на чанки (~500 токенов, перекрытие 50 символов).
4.	Для каждого чанка вычисляется эмбеддинг с помощью BAAI/bge-m3.
5.	В Chroma сохраняются: текст чанка, эмбеддинг, метаданные (book_title, author, chapter, page).
6.	Результат (количество книг, чанков) логируется и отправляется администратору.
3.5. Безопасность и лимиты JDoodle
•	Выполнение кода только через JDoodle, не на сервере бота.
•	Бесплатный тариф: 20 запросов в сутки. Бот хранит счётчик в SQLite и блокирует при превышении.
•	Логирование всех запросов к JDoodle (дата, студент, код, результат) опционально для отладки.
•	При недоступности JDoodle — сообщение студенту: «Сервис выполнения временно недоступен, попробуйте позже».
4. Этапы разработки (MVP)
1.	Настройка окружения
o	Регистрация бота в VK, получение токена.
o	Регистрация в JDoodle, получение client_id и client_secret.
o	Регистрация в DeepSeek, получение API-ключа.
o	Настройка BotHost (переменные окружения, volume).
2.	Базовый эхо-бот
o	Подключение Callback API, приём и отправка сообщений.
3.	Интеграция DeepSeek API (без RAG)
o	Бот отвечает на общие Java-вопросы, используя знания модели (временное решение).
4.	Интеграция JDoodle API
o	Выполнение Java-кода по команде /run.
o	Реализация счётчика лимитов (бесплатный тариф).
o	Административные команды /jdoodle_status, /reset_jdoodle_limit.
5.	Добавление статического персонажа
o	4 PNG, тексты, задержка перед ответом (robot_thinking.png).
6.	Настройка базы знаний (RAG)
o	Загрузка PDF-книг в /app/shared/Литература.
o	Извлечение текста, индексация в Chroma (/reload_knowledge).
o	Замена прямых запросов к DeepSeek на RAG-пайплайн.
o	Ответы только по учебникам с указанием источников.
7.	Реализация режима «страховка» для кода
o	При ошибке – немедленная выдача эталона + объяснение.
o	Команда /explain.
8.	Административные команды для библиотеки
o	/clear_knowledge, /list_files, /delete_file, /delete_folder, /status.
9.	Тестирование в группе
o	Проверка всех сценариев (теория, успешный код, ошибочный код, /explain, лимиты JDoodle).
5. Критерии приемки (MVP)
•	Бот корректно отвечает на теоретические вопросы, используя только загруженные книги (проверка: вопрос, ответ на который есть в книгах, но нет в общих знаниях DeepSeek, — бот даёт верный ответ со ссылкой на источник).
•	При отсутствии ответа в базе знаний — фраза «Я не могу найти точный ответ...» + robot_sad.png.
•	Бот выполняет Java-код через JDoodle. При успехе — robot_happy.png + вывод программы.
•	При ошибке в коде бот немедленно выдаёт эталонный код и пояснение, не дожидаясь повторных попыток.
•	Команда /explain даёт эталон без отправки кода.
•	Бесплатный тариф JDoodle: после 20 запросов в сутки бот блокирует дальнейшие вызовы и показывает сообщение о лимите.
•	Администратор может через /admin получить клавиатуру и выполнить все команды управления библиотекой и JDoodle.
•	Персонаж отправляет правильную эмоцию в каждой ситуации, задержка с robot_thinking.png соблюдена (1–3 сек).
•	Время ответа на вопрос (с RAG) не превышает 10 секунд.
•	Бот не содержит модуля тестирования, не ведёт учёт прогресса студентов (это будет в версии 2.0).
6. Документация и развёртывание
6.1. Переменные окружения (на BotHost)
Переменная	Описание
VK_TOKEN	токен сообщества VK
DEEPSEEK_API_KEY	ключ DeepSeek API
JDODDLE_CLIENT_ID	Client ID JDoodle
JDODDLE_CLIENT_SECRET	Client Secret JDoodle
JDODDLE_PLAN	free (по умолчанию) или pro
ADMIN_IDS	VK ID администратора (один)
KNOWLEDGE_ROOT	путь к корню литературы (по умолч. /app/shared/Литература)
6.2. Инструкция по развёртыванию на BotHost
1.	Установить переменные окружения.
2.	Настроить постоянное хранилище (volume) для /app/shared.
3.	Загрузить папку «Литература» через раздел «Общие файлы» (ZIP-архивом, распаковать в /app/shared/Литература).
4.	Выполнить /reload_knowledge для первичной индексации.
5.	Проверить работу команд /run и /explain.
6.3. Описание команд для студентов (публикуется в сообществе)
•	/start, /help — приветствие.
•	/run (с кодом) — выполнить Java-код (при ошибке выдаётся эталон).
•	/explain — получить правильное решение без отправки кода.
•	/about — информация о боте.
