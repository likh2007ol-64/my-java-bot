Задача: Разработать первую версию VK-бота J2J_Bot для сообщества «Java-старт | Jump2Java» согласно приложенному ТЗ, но только функционал, связанный с ответами на теоретические вопросы (RAG), визуальным персонажем и административным управлением библиотекой. Всё, что относится к выполнению и проверке Java-кода (раздел 2.2 ТЗ, команды /run, /explain, интеграция с JDoodle, счётчики лимитов) — исключить.
Язык: Java 17, Spring Boot 3, сборка Maven.

1. Общие требования
Реализовать только разделы ТЗ:

2.1 — Ответы на теоретические вопросы (многоязычный RAG на базе Chroma + BAAI/bge-m3 + DeepSeek)

2.3 — Вспомогательные команды (/start, /help, /about)

2.4 — Визуальный персонаж (статический робот, отправка PNG)

2.5.1 и 2.5.2 — Административные команды для управления библиотекой (клавиатура, /reload_knowledge, /clear_knowledge, /list_files, /delete_file, /delete_folder, /status)

2.5.3 — игнорировать (JDoodle)

Раздел 3 — Архитектура (кроме JDoodle)

Раздел 4 — кроме шагов, связанных с JDoodle.

Команды /run и /explain не реализовывать. Если студент их напишет, бот должен отвечать: «Функция проверки кода будет добавлена в следующей версии. Пока я могу отвечать только на теоретические вопросы по Java.»

Бот не должен требовать наличия переменных окружения для JDoodle. Достаточно:

VK_TOKEN

DEEPSEEK_API_KEY

ADMIN_IDS (один VK ID)

KNOWLEDGE_ROOT (по умолчанию /app/shared/Литература)

(опционально) PORT

2. Структура проекта и статические файлы
В корне проекта создать папку static.

Внутри static разместить пустые файлы-заглушки (или минимальные PNG 1x1 пиксель) с точными именами:

robot_greeting.png

robot_thinking.png

robot_happy.png

robot_sad.png

Реализовать однократную загрузку этих изображений в VK при старте бота (используя photos.getMessagesUploadServer, загрузку multipart, photos.saveMessagesPhoto). Полученные attachment-строки сохранить в памяти (Map) и использовать при отправке сообщений с эмоциями.

Если загрузка не удалась (файлы пустые или ошибка API) — вывести предупреждение в лог, но бот должен работать, отправляя вместо картинок соответствующие эмодзи (🤔, ✅, 😕).

3. Функционал теории (RAG)
3.1. Инициализация базы знаний
При старте бот проверяет, есть ли данные в Chroma. Если нет — работает в режиме «база не индексирована», на любой теоретический вопрос отвечает: «База знаний ещё не загружена. Администратор должен выполнить /reload_knowledge».

Команда /reload_knowledge (только для ADMIN_IDS):

Сканирует папку KNOWLEDGE_ROOT (рекурсивно, поддерживаются подпапки).
Извлекает текст из всех PDF-файлов (Apache PDFBox).
Разбивает на чанки (~500 токенов, перекрытие 50 символов).
Вычисляет эмбеддинги для каждого чанка с помощью BAAI/bge-m3 (модель загружается локально, можно использовать langchain4j-embeddings-bge-small или transformers через ONNX; допустимо для MVP использовать упрощённый вариант с заглушкой эмбеддингов, но нужно написать код, который реально работает с этой моделью или хотя бы с любой многоязычной, например sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 — но в ТЗ указана BGE-M3, так что постарайся её подключить).
Сохраняет чанки в Chroma (in‑memory или на диске, например в папку chroma_db) с метаданными: book_title, author (если удалось извлечь из PDF или имени файла), chapter (опционально), page.
Результат индексации (количество книг, чанков) отправляется администратору в ЛС.

Команда /clear_knowledge — очистка всей коллекции Chroma.

Команда /status — возвращает: количество книг (уникальных PDF), количество чанков, дату последней индексации (хранить в SQLite).

Команды /list_files [путь], /delete_file, /delete_folder — работа с файловой системой в пределах KNOWLEDGE_ROOT (без возможности удалить саму корневую папку).

3.2. Обработка вопроса студента
Студент пишет текст (не команду).

Бот отправляет robot_thinking.png + «Секунду, думаю... 🤔».

Выполняет векторный поиск в Chroma (3–5 релевантных чанков).

Формирует промпт для DeepSeek API:

text
Ответь на русском языке, основываясь строго на предоставленных фрагментах.
Если ответа нет во фрагментах, скажи «Я не могу найти точный ответ на этот вопрос в нашей учебной базе. Попробуйте переформулировать запрос».
Не используй свои знания.
Укажи источник(и) информации: название книги, автор, главу (если есть).

Вопрос: {question}

Фрагменты:
{chunks}
Температура 0.2.

Отправляет запрос в DeepSeek API (модель deepseek-chat).

Полученный ответ отправляет студенту вместе с robot_happy.png (если ответ найден) или robot_sad.png (если не найден).

Задержка между отправкой thinking и основным ответом — 1–3 секунды (можно реализовать через Thread.sleep или планировщик).

4. Вспомогательные команды
/start или /help → robot_greeting.png + текст:
*«Привет! Я Java-робот 🤖. Помогаю студентам JUMP2JAVA с теорией. Спроси меня о Java — я отвечу на основе учебников. (Проверка кода появится позже)»*

/about → информация о боте, версия (1.0 – теория).

5. Административный интерфейс
В ЛС администратор пишет /admin → бот отправляет клавиатуру с кнопками (InlineKeyboardMarkup или обычная клавиатура):

🔄 Переиндексировать всё

🗑 Очистить базу

📂 Показать файлы

❌ Удалить файл/папку

ℹ️ Статус библиотеки

При нажатии на каждую кнопку выполняется соответствующая команда (как если бы администратор написал её текстом). Результат отправляется в ЛС.

Команда 📦 Обновить из ZIP — не реализовывать (заглушка: «Будет в версии 2.0»).

6. Базы данных
Chroma — векторное хранилище.

SQLite — для хранения:

library_metadata (последняя дата индексации, количество книг/чанков).

(опционально) логи.

7. Обработка ошибок
Если DeepSeek API недоступен — отвечать: «Сервис ответов временно недоступен, попробуйте позже» + robot_sad.png.

Если при индексации какой-то PDF не читается — пропустить файл, записать ошибку в лог.

Если пользователь не администратор пытается выполнить /reload_knowledge или другие админ-команды — отвечать «У вас нет прав».

8. Завершающий этап
После сборки проекта и проверки работоспособности (все перечисленные функции работают, бот отвечает на вопросы по учебникам) — вывести в консоль:

text
✅ Фаза 1 бота J2J_Bot завершена.
   - Реализованы: ответы на теорию через RAG (Chroma + BGE-M3 + DeepSeek), персонаж, управление библиотекой.
   - Команды /run и /explain отключены (заглушка).
   - Заполните секреты: VK_TOKEN, DEEPSEEK_API_KEY, ADMIN_IDS.
   - Замените файлы в static/ на реальные PNG.
   - Запустите приложение и протестируйте.
Примечание для агента:
Если реализация BAAI/bge-m3 в Java через LangChain4j вызывает трудности, допустимо использовать org.langchain4j:langchain4j-embeddings-all-minilm-l6-v2 (английский) и параллельно переводить запросы на английский, но это отступление от ТЗ. Лучше попытаться подключить langchain4j-embeddings-bge-small (см. mvnrepository). Главное — чтобы бот искал релевантные фрагменты и отвечал по ним. При полной невозможности — сделай заглушку с поиском по ключевым словам, но с комментарием, что это временное решение.
